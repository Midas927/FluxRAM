Boost-first

每次操作都有边界

FluxRAM 不以“清得越多越好”为目标。一次 Boost 先判断压力和风险，再对合适的冷后台进程收缩工作集。

  1. 1
    检查内存压力

    Auto Boost 只在达到当前档位阈值且冷却完成后触发。

  2. 2
    筛选低风险候选

    综合前后台状态、CPU、I/O、冷度和保护名单决定是否处理。

  3. 3
    裁剪并解释结果

    展示裁剪量、净收益、回弹率，以及为什么执行或跳过。

强力，但由你确认

Boost 不替你关前台应用

普通 Boost 只做工作集裁剪，不直接关闭软件。需要释放真正不再使用的高占用应用时，Pro 的 Extreme Close 会先列出候选，再由你勾选确认。

常见问题

先把疑虑说清楚

会用固态硬盘寿命换内存空间吗？

FluxRAM 的核心操作是请求 Windows 收缩候选进程的工作集，不会主动把内存内容写成自己的磁盘缓存，也不会刻意增加 SSD 写入。被裁剪页面之后若再次访问，Windows 可能重新从文件或页面文件载入，所以频繁、无差别裁剪反而可能让应用变慢；这正是 FluxRAM 要筛选冷后台并限制 Auto Boost 频率的原因。

能提升 FPS 吗？

FluxRAM 不承诺直接提高 FPS。它解决的是内存压力和冷后台占用问题；当卡顿确实来自内存紧张时可能改善体验，CPU、GPU 或网络瓶颈则不在它的处理范围内。

为什么有时 Boost 释放得不多？

可能是当前内存压力不高，或高占用进程仍然活跃、属于游戏/系统进程、已被保护。FluxRAM 会在详细界面给出候选预览和跳过原因，不会为了数字好看而处理高风险目标。

Windows 为什么提示“未知发布者”？

当前公开版本尚未购买代码签名证书，因此 Windows 可能显示未知发布者。安装包发布在本项目 GitHub Releases，并附带 SHA256 校验文件；源代码也可公开审查。
