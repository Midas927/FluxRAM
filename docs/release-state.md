# FluxRAM Release State

## 当前版本线

- 当前正式版：0.4
- 当前测试版：无
- 下一测试版：待定
- 下一正式版：待定
- 发布分支：main

## 0.3.6-beta.1 已纳入

- 开机 Auto Boost 启动时静默驻留托盘，不弹主窗口。
- 新增 Gaming 档位，面向游戏 PC 和 Windows 掌机。
- Gaming 档位启用内置游戏/掌机相关进程保护名单。
- 无候选或无裁剪时显示更明确原因。
- 保留 0.3.5 的详细界面滚动修复和滚动条加粗。

## 0.3.6 正式版已纳入

- 模式收敛为 Daily / Gaming / Extreme。
- 新安装默认选择 Gaming。
- 旧 Standard / Balanced 设置迁移到 Gaming。
- 档位说明窗口支持滚动和调整大小，内容过长时不再卡住。
- 手动 Boost / Preview 比 Auto Boost 更积极，Auto Boost 继续保持保守。
- 新增 Extreme Close：用户主动确认后关闭高占用应用。
- Extreme Close 可列出前台高占用应用，但默认不勾选前台项。
- 受保护应用列表限制显示高度，列表内优先响应滚轮，到边界后继续滚动详情页。
- 内存指标中的自身开销改为整行换行显示，不再截断。
- Extreme Close 排除 Windows 系统进程白名单，避免提供高风险关闭候选。

## 0.3.7 正式版已纳入

- 调整版本功能展示：Extreme Close 归入 Pro，并同步程序界面与产品说明。
- 同步普通版 / Pro 版本说明，明确 Extreme Close、Extreme 档位和高级应用保护属于 Pro。
- 应用、官网和更新检测版本统一为 0.3.7。
- 自动化测试 81/81 通过，Lite / Portable 发布包构建成功，EXE FileVersion 为 0.3.7.0。

## 0.3.8-beta.1 已纳入

- 检查更新升级为应用内下载、SHA256 校验、替换和重启流程。
- 更新成功启动后自动清理旧 EXE 与本次更新缓存；替换失败时保留原程序。
- Lite / Portable 发布包写入分发模式，更新时自动选择对应包。
- Beta 输出到 `dist/beta` 并带完整预发布版本文件名，不覆盖正式版本地资产。
- 预发布版本参与更新比较，Beta 可以正确识别后续 Beta 与正式版。
- 正式版只读取正式 Release，Beta 通道同时读取预发布与正式 Release。
- Extreme Close 更名为 Deep Release / 深度释放，仍由用户选择并确认要关闭的应用。
- 精确路径、子进程与关联窗口统一为“智能关联保护”，普通 Boost 与深度释放共用同一套保护判断。
- 收紧关联窗口判断，浏览器页面标题不再触发关联保护。
- Pro 界面显示每次实际保护的进程数量和命中类型。

## 0.3.8-beta.2 已纳入

- 普通 Boost 改为按应用族汇总内存：同目录或同父子链的碎片进程合并判断，候选上限按应用而非进程计算。
- 应用族任一成员位于前台、活动量过高、受保护或处于冷却期时，普通 Boost 会整组跳过。
- Boost 预览与执行明细改为应用级汇总，不再被同一应用的多个子进程刷屏。
- 深度释放按安装目录和父子链合并不同名称的后台组件，展示门槛降至 32 MB；低于 96 MB 的项目默认不勾选。
- 有可见窗口的应用只展示、不默认勾选；安全软件、共享 WebView 与 Windows 外壳组件不进入关闭候选。
- 深度释放新增可选后台服务：只显示正在运行且支持正常停止的目标，动态后缀服务可以识别，所有服务默认不勾选。
- 与候选应用同属一个进程族的独立服务可进入服务列表；共享 Windows 宿主进程不会被直接结束。

## 0.3.8-beta.3 已纳入

- 深度释放中的每条后台服务明确标记为“系统服务”或“应用服务”。
- 服务增加“建议保留”“不用该功能时可关”“可随应用关闭”三档操作建议，建议保留项使用警示色。
- 应用关联服务优先排列，服务名称拆为第二行，避免分类标签加入后挤压显示。
- 所有后台服务继续默认不勾选，悬停可查看停止影响说明。

## 0.3.8-beta.4 已纳入

- 新增按应用族持续采样的后台积累识别，记录首次观察与最近明显活动时间。
- 普通状态每 15 秒低频观察；Auto Boost 或回弹监测期间沿用 3 秒采样。
- 深度释放候选标记为“闲置后台”“后台工作中”“有窗口”或“观察中”，并显示判断依据。
- 只有连续观察至少 60 秒、至少 5 个样本且期间无前台、可见窗口或明显 CPU/磁盘活动的应用才会标记为闲置。
- 无窗口后台应用的展示门槛由 32 MB 降至 12 MB，同一应用的零碎进程继续合并计算，便于发现多个小型驻留组件。
- 深度释放顶部显示后台应用数量与累计内存；观察不足、近期活动和可见窗口应用不会默认勾选。
- 窗口状态改为识别实际可见且未最小化的窗口，最小化或托盘化应用可在重新观察满 60 秒后进入闲置判断。

## 0.3.8-beta.5 已纳入

- 深度释放从工具菜单提升到主界面操作区，与立即 Boost、自动 Boost 并列展示。
- Pro 用户点击主界面“深度释放”后直接进入后台积累候选列表。
- 普通版始终显示“深度释放 · PRO”入口并使用区别样式，点击后打开版本功能对比与现有升级流程。
- 工具菜单移除重复的深度释放入口，避免同一功能出现在两个位置。
- 三操作区固定为等宽列，确保中英文标签在紧凑窗口内保持对齐。

## 0.4 正式版已纳入

- 汇总 0.3.8-beta.1 至 beta.5 的全部改动，正式版本号提升为 0.4。
- 普通 Boost 按应用族汇总零碎进程，整组执行前台、活动状态、保护与冷却判断。
- 深度释放升级为核心 Pro 功能：持续观察后台活动、识别闲置应用、汇总累计内存，并支持用户确认关闭。
- 深度释放可列出 12 MB 以上的无窗口后台应用；只有观察充分且累计达到 96 MB 的闲置应用才可能预先勾选。
- 可选后台服务区分系统服务与应用服务，并给出“建议保留”“不用该功能时可关”“可随应用关闭”提示。
- 深度释放入口提升到主界面；普通版显示清晰的 Pro 标识和版本对比入口，Pro 用户直接执行。
- 检查更新支持应用内下载、SHA256 校验、原位替换、重启以及成功后的旧文件清理。
- Lite 与 Portable 会在应用内更新时自动选择对应分发包。
- 正式版自动化测试通过：150/150。


## 已确认用户反馈

- 开机自启弹主窗口，用户感知像广告。
- 32 GB 内存玩网游时 Standard 档位可能没有裁剪量，用户感知为“没效果”。
- 详细界面最近活动列表堆叠、滚动条过小、滚轮焦点不符合预期。
- 档位说明的问号弹窗内容过长时不能滚动。
- 用户会拿 FluxRAM 和 Mem Reduct、Process Lasso 这类工具比较。
- 用户希望有强力关闭高占用应用的能力，但普通 Boost 不能自动关前台应用。
